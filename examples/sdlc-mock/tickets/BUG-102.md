# BUG-102: Balance request fails when the account id is typed in lower case

**Reported by:** support (customer ticket 4502)
**App:** accounts
**Status:** Open

## Description

The mobile app sends account ids as the customer typed them. `GET /accounts/acc-1/balance`
returns HTTP 404 although ACC-1 exists, so the customer sees "account not found" for their
own account. Account ids are letters and digits with no meaning in their case; the ledger
stores them in upper case.

## Acceptance criteria

- AC1: `GET /accounts/acc-1/balance` returns 200 with `"balance":"150.00"`.
- AC2: `GET /accounts/ACC-1/balance` still returns 200 with `"balance":"150.00"`.
- AC3: `GET /accounts/nope/balance` still returns 404.
- The unit tests pass, and the application log shows the balance computed for the account
  asked for as `acc-1`.
